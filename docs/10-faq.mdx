# FAQ

Common questions and answers about git-hop.

## General

### What is git-hop?

git-hop is a Git subcommand that wraps `git worktree` with isolated, stable multi-branch development environments. It manages ports, volumes, and Docker services automatically.

### Do I need Docker?

Docker is optional for basic git-hop usage. However, if you want automatic service orchestration, Docker is required.

### Is git-hop a replacement for git worktree?

No, git-hop builds on top of git worktree. It enhances worktrees with environment management, resource allocation, and service orchestration.

### Can I use git-hop with existing worktrees?

Yes! git-hop can manage worktrees you've already created. Run `git hop` in a directory with existing worktrees to have git-hop manage them.

## Installation

### How do I install git-hop?

Build from source:

```bash
git clone https://github.com/hop-top/git.git git-hop
cd git-hop
make build
sudo mv git-hop /usr/local/bin/
```

git runs `git hop` by finding a `git-hop` binary on `PATH`. Don't use
`go install hop.top/git@latest`: it names the binary `git`, which shadows
git itself.

### What are the requirements?

- Git 2.7 or higher (2.38+ for content-based merge detection in `remove`)
- Go 1.26 or higher (for building)
- Docker (optional, for services)

### Can I install git-hop without Go?

Not yet: there are no pre-built binaries. Building from source needs Go.

## Usage

### How do ports get allocated?

A worktree with a Docker environment gets a block of ports when it is set
up, recorded in the hopspace's `ports.json`, and keeps them from then on:

```bash
git hop add feature-x              # Gets ports 10003-10005
cd hops/feature-x
git hop env generate               # Still 10003-10005
```

New ports go after the highest port in use by any hub git-hop knows of
(`allocationMode: incremental`, the default), so they depend on what is
already allocated: the same branch in another hub or on another machine
can get other ports. Setting `allocationMode` to `hash` in `ports.json`
opts into placing new blocks where the repository, hub and branch hash to.

### Can I manually set ports?

git-hop allocates them, and a worktree keeps its ports from then on. You
can move the range new ports come from: edit `baseRange` in
the hopspace's `ports.json` (in the hub for a default clone):

```json
{
  "baseRange": { "start": 20000, "end": 30000 }
}
```

### What if there's a port conflict?

git-hop automatically detects conflicts and allocates alternative ports. Run `git hop doctor` to check for issues.

### How do I clean up old branches?

```bash
# Remove a specific branch
git hop remove feature-x

# Drop the records of worktrees and hubs whose directories are gone
git hop prune
```

Neither stops or removes the branch's containers: run `git hop env stop`
in the worktree first (see
[Orphaned Resources](./08-advanced-usage#orphaned-resources)).

### How do I clean up all merged branches?

```bash
# Interactive (prompts before each removal)
git hop remove --merged

# Scripted (no prompts)
git hop remove --merged --no-prompt
```

`--merged` removes every worktree whose branch is merged into the
hub's default branch. It skips the default branch itself and the
worktree you're currently in. Each candidate still goes through the
standard safety gate, so a dirty merged branch needs `--no-verify`
just like a single-target remove would.

### What's the difference between `prune`, `remove`, `env gc`, and `doctor`?

They sound similar but solve different problems:

- **`git hop prune`** — removes orphan **state entries** (worktrees
  and hubs whose paths are gone), repair backups older than
  `hop.repair.backupRetention`, and `git hop init` conversion backups
  beyond `hop.backup.maxBackups` / `hop.backup.cleanupAgeDays`. It does not touch existing worktrees,
  and never runs Docker.
- **`git hop remove`** — removes a specific worktree (or all merged
  ones with `--merged`). Touches the worktree on disk plus its state,
  not its containers: `git hop env stop` stops those.
- **`git hop env gc`** — reclaims orphaned dependency directories
  (e.g. `node_modules` snapshots no longer used by any branch).
- **`git hop doctor --fix`** — repairs inconsistent state: missing
  hopspaces, broken symlinks, divergent registries. Auto-drops missing
  worktree entries whose branch is merged into default.

## Troubleshooting

### git hop command not found

Make sure git-hop is in your PATH:

```bash
# Check installation
which git-hop

# Add to PATH if needed
export PATH="$PATH:/usr/local/bin"

# Verify
git hop --version
```

### Environment won't start

Check Docker is running:

```bash
docker ps

# Start Docker
sudo systemctl start docker  # Linux
open -a Docker            # macOS
```

Then check the environment git-hop generated:

```bash
cd your-branch
cat .env        # HOP_PORT_* and HOP_VOLUME_* values
git hop doctor
```

### Services are conflicting

Ensure each branch has unique ports:

```bash
git hop
# Check ports column for duplicates
```

No two worktrees get the same port, across every hub git-hop knows of.
Where two hubs already hold one port (from an earlier release, or a
copied `ports.json`), the hub set up first keeps it. `git hop doctor`
names the other one; generate its environment again to give it new
ports:

```bash
git hop doctor
cd path/to/other/hub/hops/feature-x
git hop env generate
```

git-hop does not probe the host: a port something outside git-hop holds
is not detected. Move the range in the hopspace's `ports.json`
(`baseRange`) so new ports avoid it.

### Worktree is broken

A worktree directory that is gone: `git hop doctor --fix` checks the
branch out again at the same path. A branch already merged into the
default branch is cleaned up instead; `git hop add feature-x` checks it
out again if you still want it.

```bash
cd my-project
git hop doctor --fix -n   # preview
git hop doctor --fix
```

A worktree that is there but that git no longer recognises (a stale
`.git` pointer after a move, a missing registration): `git hop repair`
fixes the metadata, with a backup (`-n` previews, `--undo` reverts).

```bash
git hop repair
```

## Performance

### Does git-hop slow down Git operations?

No, git-hop is very lightweight. It only adds minimal overhead for resource allocation and service management.

### How much disk space does git-hop use?

Each hopspace shares the git object database with the hub. Only working files are duplicated, typically 10-100MB per branch.

### Can I limit disk usage?

Yes. Regular pruning helps, and dependency installs are shared across
worktrees with the same lockfile:

```bash
# Regular pruning
git hop prune
```

## Advanced

### Can I use git-hop in CI/CD?

Yes! git-hop works great in CI/CD pipelines:

```yaml
# GitHub Actions
- name: Install git-hop
  run: |
    git clone --depth 1 https://github.com/hop-top/git.git /tmp/git-hop
    make -C /tmp/git-hop build
    echo /tmp/git-hop >> $GITHUB_PATH
  
- name: Create environment
  run: |
    git hop origin/main
    cd main
    git hop env start
    make test
```

### Can I integrate git-hop with my editor?

Yes! git-hop works with all editors. Configure your editor to recognize worktrees:

**VS Code:**
```json
{
  "git.openRepositoryInParentFolders": "always"
}
```

**Vim/Neovim:**
```vim
autocmd BufEnter * silent! lcd %:p:h:gs/^.*my-project\///:h
```

### Can I use custom hooks?

Yes! git-hop supports custom Git hooks:

```bash
# .git-hop/hooks/post-env-start
#!/bin/bash
npm install
make db-migrate
```

See [Integration](./07-integration) for more details.

## Security

### Is git-hop safe?

Yes! git-hop only manages local resources and doesn't expose any network services. All operations run on your local machine.

### Does git-hop access my Git credentials?

git-hop uses your existing Git configuration. It doesn't store or access credentials directly—it delegates all Git operations to your installed git binary.

### Can I use git-hop with private repositories?

Yes! git-hop works with any Git repository, public or private. It uses your existing Git authentication.
