# Reference

Complete reference for git-hop commands, configuration, and APIs.

## Commands Reference

### Global Flags

| Flag | Type | Description |
|------|-------|-------------|
| `--format &lt;format&gt;` | string | Result format: `table` or `human` (the default human view), `json`, `yaml`, `csv`, `text`. See [Structured Output](#structured-output) |
| `--json` | bool | Same as `--format json` |
| `--porcelain` | bool | One tab-separated record per line, no header. See [Structured Output](#structured-output) |
| `--cols &lt;list&gt;` | string | Select and order the columns of `csv`, `text` and `--porcelain` output |
| `--format-opt style=&lt;style&gt;` | string | Layout of `--format text`: `kv` (default), `lines` or `paragraph` |
| `--quiet, -q` | bool | Only report errors: drops progress, hints and warnings, never `error:`/`fatal:` |
| `--verbose, -V` | count | Increase log verbosity; repeatable (`-V` debug, `-VV` trace) |
| `--force` | bool | Bypass safety checks (use with caution) |
| `--global, -g` | bool | Use the global hopspace in `$GIT_HOP_DATA_HOME` (default: local) |
| `--config, -c &lt;value&gt;` | string array | Ignored, with a `warning:` on stderr that `-q` does not drop; accepted so old scripts still run, and not listed in `--help`. Settings live in git config `hop.*`. For a one-off setting use git's own `-c`: `git -c hop.&lt;key&gt;=&lt;value&gt; hop ...` |
| `--dry-run, -n` | bool | Show what would happen without making changes |
| `--no-color` | bool | Disable ANSI color |
| `--no-hints` | bool | Suppress next-step hints after command output |
| `--offline` | bool | Disable network access |
| `--help, -h` | bool | Show help for command |
| `--version, -v` | bool | Show git-hop version (top-level `git hop` only) |

### git hop `&lt;uri&gt;`

Clone a repository into a new hub and hopspace.

**Synopsis:**
```bash
git hop [flags] &lt;uri&gt; [&lt;path&gt;]
```

`&lt;uri&gt;` is a git URL (`git@host:org/repo.git`, `https://...`, anything
ending in `.git`) or an `org/repo` shorthand, expanded to
`git@&lt;domain&gt;:org/repo.git`. Inside a hub, a word that names a registered
worktree switches to it instead. `&lt;path&gt;` is the hub directory to create
(default: the repository name, in the current directory); it must not exist.

**Flags:**
| Flag | Description |
|------|-------------|
| `--git-domain &lt;domain&gt;` | Host for expanding an `org/repo` shorthand (default: `defaults.gitDomain` in the global config, else `github.com`) |
| `--hooks &lt;mode&gt;` | Mirror committed `.git-hop/hooks/` into the hopspace: `symlink`, `copy`, `prompt` or `none`. Falls back to `$GIT_HOP_HOOKS`, then `git config hop.hooks.installMode`, then `prompt`; without a terminal, `prompt` installs nothing |
| `--hooks-overwrite` | Overwrite a hopspace hook whose content differs (`symlink` and `copy` modes) |
| `--branch &lt;name&gt;` | Inside an existing hub only: attach `&lt;uri&gt;` as a fork and check out `&lt;name&gt;` from it, instead of cloning a new hub; outside a hub it is a usage error, never ignored. A branch sharing no history with the hub is refused. Attaching a branch again, or finishing an attach that stopped halfway, reuses the worktrees already there and fast-forwards them to the fork's branch; one on another branch, holding commits the fork does not have, or with local changes the update would overwrite is refused and left as it is. Each refusal prints a `hint:` saying how to get past it; `--force` overrides none of them |
| `--env-start` | Start the environment of the worktree the clone creates, as `git hop env start` would. Without it or `--no-env-start`, `$GIT_HOP_AUTO_ENV_START` and then `git config hop.env.autoStart` (default `false`) decide. A failed start warns and hints at `git hop env start`; the clone still exits 0 |
| `--no-env-start` | Do not start it, whatever `hop.env.autoStart` says |

[Global flags](#global-flags) apply; `-g, --global` puts the hopspace under
`$GIT_HOP_DATA_HOME`. Clone has no preview, so `-n, --dry-run` is refused.
With `--json`, `--format` or `--porcelain` a clone prints the
[root command's result](#root-command) (`action: cloned`, or
`fork-attached` with `--branch`) and nothing else on stdout.

**Exit Codes:**
| Code | Description |
|------|-------------|
| 0 | Success |
| 1 | Clone failed: repository unreachable, `&lt;path&gt;` already exists, or a `pre-clone` hook aborted |
| 128 | `$GIT_HOP_AUTO_ENV_START` is not a boolean |
| 129 | Usage error: unknown flag, bad flag value, `--dry-run`, or `--branch` outside a hub. Prints `error:` (or `fatal:` for `--dry-run` and `--branch`) on stderr |

### git hop add

Create a worktree (and branch, if needed). Aliases: `create`, `new`.

**Synopsis:**
```bash
git hop add &lt;branch&gt; [flags]
```

**Flags:**
| Flag | Description |
|------|-------------|
| `--from <ref>` | Start-point for a new branch (branch, ref, SHA, or `initial`); fast-forwards an existing local branch to `<ref>`, refuses if it is ahead or diverged |
| `--copy-ignored` | Copy git-ignored local files from the fork-source worktree (default) |
| `--no-copy-ignored` | Skip that copy for this worktree |
| `--env-start` | Start the new worktree's environment once it exists, through the same code as `git hop env start` |
| `--no-env-start` | Do not start it, whatever `hop.env.autoStart` says |
| `--fetch` | Run `git fetch origin` before resolving the start-point; a failed fetch is fatal |
| `--no-fetch` | Do not fetch. Without either, `hop.add.fetch` decides; unset, add fetches (warning on failure) only when the start-point is an origin ref |
| `--task <id>` | Record a task id for the worktree (metadata only); without `<branch>`, derive the branch from the task via `tlc` |

Without either env-start flag, `$GIT_HOP_AUTO_ENV_START` and then
`git config hop.env.autoStart` (default `false`) decide. The start is
skipped silently when the worktree has no environment; a failed start
prints `warning:` and a `hint:` to run `git hop env start`, and add still
exits 0. `--dry-run` reports `Would start environment` when it would try.

**Related git config:** `hop.env.autoStart`, `hop.add.copyIgnored`, `hop.add.copyIgnoredMaxSize`
— see [Configuration](configuration.md#hopaddcopyignored). A `#-hop-#`
comment line directly above a `.gitignore` pattern excludes that pattern's
entries from the copy.

### git hop `&lt;branch&gt;`

Switch to an existing worktree: run `pre-worktree-switch`, point the hub's
`current` symlink at the worktree, run `post-worktree-switch`. Creates
nothing; [`git hop add`](#git-hop-add) does. The shell integration `cd`s
into `current` afterwards.

**Synopsis:**
```bash
git hop [-n] &lt;branch&gt;
```

`&lt;branch&gt;` must be registered in the hub's `hop.json`. No flags of its
own (`--branch` is a usage error here); `-n, --dry-run` names the hooks and the `current` target without
running or writing anything. With `--json`, `--format` or `--porcelain`
it prints the [root command's result](#root-command) (`action:
switched`), also on exit 93.

**Exit Codes:**
| Code | Description |
|------|-------------|
| 0 | Switched |
| 1 | Branch not registered in the hub, not in a hub, or `pre-worktree-switch` aborted |
| 93 | Switched; `post-worktree-switch` navigated itself (see [Exit Codes](#exit-codes)) |
| 129 | Usage error: unknown flag, or `--branch` |

### git hop

With no arguments, print help (as `git hop --help`) and exit 0, in every
output mode: help is never a result. To see the
worktrees, use `git hop list`; for machine-readable output, add `--json`,
`--format` or `--porcelain` (see [Structured Output](#structured-output)).

Help lists the daily commands. `doctor`, `repair` and `prune` form the
MANAGEMENT group, left out of `--help`: `--help-all` lists every command,
`--help-management` or `git hop help management` only those three.

**Synopsis:**
```bash
git hop [flags]
```

### git hop status

Show the status of the current worktree or hub, or of `&lt;target&gt;`.
Aliases: `st`, `info`.

**Synopsis:**
```bash
git hop status [&lt;target&gt;] [flags]
```

**Flags:**
| Flag | Description |
|------|-------------|
| `--all` | Show every tracked repository, its worktrees, configuration and resource use; works outside a hub |

**Exit Codes:**
| Code | Description |
|------|-------------|
| 0 | Success, including the human view outside a hub (`Not in a hub or worktree.`) |
| 1 | `&lt;target&gt;` not registered in the hub, `&lt;target&gt;` given outside a hub, or the hub's `hop.json` unreadable |
| 128 | Structured output (`--json`, `--format`, `--porcelain`) without `--all` outside a hub |
| 129 | Usage error |

### git hop env start

Start the current worktree's environment services. Alias: `up`.

**Synopsis:**
```bash
git hop env start
```

No flags of its own; `--dry-run` is refused. Uses the hub's
`settings.environmentManager` when set, otherwise the first environment
manager whose detect files the worktree has, and runs the hub's
`settings.environmentConfig.hooks.preStart` / `postStart` around it.

**Exit Codes:**
| Code | Description |
|------|-------------|
| 0 | Started, or skipped because the worktree has no environment |
| 1 | Not inside a git worktree, or the start failed |
| 129 | `--dry-run`, or another usage error |

### git hop env stop

Stop the current worktree's environment services. Alias: `down`.

**Synopsis:**
```bash
git hop env stop
```

No flags of its own; `--dry-run` is refused. Runs the hub's `preStop` /
`postStop` hooks the same way.

**Exit Codes:**
| Code | Description |
|------|-------------|
| 0 | Stopped, or skipped because the worktree has no environment |
| 1 | Not inside a git worktree, or the stop failed |
| 129 | `--dry-run`, or another usage error |

### git hop env generate

Write the current worktree's environment files (`.env`, compose override)
without starting anything.

**Synopsis:**
```bash
git hop env generate
```

No flags of its own; `--dry-run` is refused.

### git hop remove

Remove a hub, hopspace, or branch.

Aliases: `rm`, `delete`, `del`.

**Synopsis:**
```bash
git hop remove [&lt;target&gt;] [flags]
git hop remove --merged [flags]
```

**Flags:**
| Flag | Description |
|------|-------------|
| `--force` | Global flag; allows removing a branch not merged into the default branch. Never covers a dirty worktree |
| `--no-verify` | Allow removal despite uncommitted or untracked files or unpushed commits. Never covers an unmerged branch |
| `--no-prompt` | Skip the confirmation prompt only; never bypasses the safety gate |
| `--merged` | Remove every worktree whose branch is merged into the default branch (skips the default branch and the active worktree) |
| `--delete-remote` | Also delete the branch on `origin`; without it removal stays local |

With `hop.gitflow.enabled`, a branch `git flow finish` handles needs
neither flag for being unmerged or unpushed: finish merges it into its
type's parent before the worktree goes. Its worktree must be clean, whatever
the flags (see Git-Flow Integration in `docs/hooks.md`).

**Exit Codes:**
| Code | Description |
|------|-------------|
| 0 | Removed, or the prompt was answered `n` (`Cancelled.`) |
| 1 | Target not found, the safety gate refused, the worktree could not be removed (git refused, or the directory is not a registered worktree and is not empty), or removal failed; the gate and the worktree refusals also under `--dry-run` |
| 129 | Usage error: no target and no `--merged`, a target beside `--merged`, or more than one target; or the confirmation prompt has no readable stdin (pass `--no-prompt`) |

### git hop prune

Remove orphaned state entries, `hop.json` rows, aged-out repair and
conversion backups, and temp files interrupted `hop.json` saves left;
with `--all`, aged-out state backups and `state.json` temp files too. Scoped
to the current repository unless `--all` is given.

**Synopsis:**
```bash
git hop prune [flags]
```

**Flags:**
| Flag | Description |
|------|-------------|
| `--all` | Prune every repository in state, not just the current one |
| `--dry-run` | Show what would be removed without action |

**Exit Codes:**
| Code | Description |
|------|-------------|
| 0 | Success |
| 1 | Prune failed, or run outside any known repository without `--all` |

### git hop doctor

Check for inconsistencies.

**Synopsis:**
```bash
git hop doctor [flags]
```

**Flags:**
| Flag | Description |
|------|-------------|
| `--fix` | Automatically fix issues found |
| `--dry-run` | With `--fix`, report repairs without applying any (no writes, no backups) |

**Exit Codes:**
| Code | Description |
|------|-------------|
| 0 | Healthy, or only warnings found. With `--fix`, every issue was fixed; with `--fix --dry-run`, every issue would be |
| 1 | An issue was reported and not fixed (without `--fix`, any issue), a repair failed, or a fatal error (for example, the working directory cannot be read) |

Like `git fsck`, the report is printed either way; the status is the
verdict. An issue counts as fixed when a `fixed` (or, under `--dry-run`,
`would-fix`) [record](#doctor) names the same `check` and `subject`.

## Structured Output

Every command that does something renders a result in the format chosen
by `--format`, `--json` or `--porcelain`. In those modes stdout carries
the result and nothing else: progress, hints, warnings and hook output go
to stderr or are suppressed.

Diagnostics follow git's streams. `error:` and `fatal:` lines always
print on stderr, in every mode and under `-q` (a JSON record under
`--json`). `warning:` lines stay on stderr under `--porcelain` and the
other formats, as git keeps them beside `--porcelain` output. `-q` drops
warnings and hints, whatever the format, but never errors.

| Mode | Output |
|------|--------|
| (default), `--format table`, `--format human` | Human view (tables, prose) |
| `--format json`, `--json` | One JSON document |
| `--format yaml` | One YAML document |
| `--format csv` | Header row, then one row per record |
| `--format text` | `key=value` lines per record; `--format-opt style=lines` or `style=paragraph` for the other layouts |
| `--porcelain` | One tab-separated record per line, no header (`--format text` in `lines` style) |

### Result shapes

Each command publishes its shape as an output schema, reflected from the
same type it renders, so the schema cannot drift from the output.

| Command | Result | Shape |
|---------|--------|-------|
| `git hop <branch>`, `git hop <uri>` | object | [root command](#root-command) |
| `git hop add` | object | [add](#add) |
| `git hop status` | list | [status](#status) |
| `git hop list` | list | [list](#list) |
| `git hop remove` | list | [remove](#remove) |
| `git hop move` | object | [move](#move) |
| `git hop merge` | object | [merge](#merge) |
| `git hop init` | object | [init](#init) |
| `git hop doctor` | list | [doctor](#doctor) |
| `git hop prune` | list | [prune](#prune) |
| `git hop repair` | list | [repair](#repair) |
| `git hop env start` | object | [env start, env stop](#env-start-env-stop) |
| `git hop env stop` | object | [env start, env stop](#env-start-env-stop) |
| `git hop env generate` | object | [env generate](#env-generate) |
| `git hop env gc` | list | [env gc](#env-gc) |

Rules:

- `--json` with `--porcelain`, or `--json`/`--porcelain` with a different
  `--format`, is refused with exit 129 before the command does anything.
  So is an unknown format or an unknown `--cols` column.
- A command with no result shape refuses `--json`, `--porcelain` and a
  structured `--format` with exit 129, before it does anything, rather
  than print prose (or nothing) where a result is expected. Only
  `upgrade` and `upgrade preamble` have none. The read-only helpers
  whose output is not a result -- `completion`, `help` and the
  shell-integration plumbing `__current-path` and `__notify-chdir` --
  accept the output flags and print what they always print. The bare
  `git hop` prints help and no result; `--version` prints the version.
- An object result is one JSON/YAML document; a list result is a list of
  records, one line each under `--porcelain`. An empty list is `[]` (and
  no lines under `--porcelain`), never empty stdout.
- `csv`, `text` and `--porcelain` carry the columns listed for each shape
  below, in that order. Fields marked *json/yaml only* appear in `json`
  and `yaml` alone, so the columnar layouts stay stable.
- Result shapes are versioned together (currently 1.13): a MINOR bump adds
  fields or enum values, a MAJOR bump renames or removes them.
- Under `--dry-run`, `add`, `init`, `remove`, `move`, `merge`, `doctor
  --fix`, `prune`, `repair`, `env gc` and branch switch render the result
  the run would produce, in the same shape; `json` and `yaml` add
  `dry_run: true` where the shape has the field (absent on a real run),
  and the list shapes name the would-be action (`would-fix`, `would-prune`,
  `would-delete`). A preview the real run would refuse fails the same
  way, with no result; `add`, `remove`, `move` and `merge` word it
  `[dry-run] would refuse to <action>: <reason>`.
- A refusal or failure keeps its exit status and reports on stderr (the
  JSON error record under `--json`); stdout then carries no result,
  except where a shape below says otherwise.

The examples below are `--json` output, indented for reading; a real run
prints them compactly or indented alike. Paths are illustrative.

### add

One object.

| Field | Type | Meaning |
|-------|------|---------|
| `branch` | string | Branch checked out in the new worktree |
| `path` | string | Absolute path of the new worktree |
| `base` | string | Branch `status` and `list` compare this worktree against |
| `upstream` | string | Upstream the branch tracks (for example `origin/main`); empty when none, and under `--dry-run` for a branch add would create (git sets it on creation) |
| `created` | bool | `true` when this run created the local branch (or, under `--dry-run`, would); `false` when an existing local branch was checked out |
| `ports` | map service → port | *json/yaml only*; present when the worktree has a Docker environment; absent under `--dry-run` (allocated once the worktree exists) |
| `task` | string | *json/yaml only*; task id recorded with `--task`; absent when none |
| `env_started` | bool | *json/yaml only*; `true` when add started the worktree's environment (`--env-start`, `hop.env.autoStart`), or under `--dry-run` would try; absent otherwise |
| `dry_run` | bool | *json/yaml only*; `true` under `--dry-run`, absent otherwise |

```json
{
  "branch": "feat/login",
  "path": "/home/me/src/widget/hops/feat/login",
  "base": "main",
  "upstream": "",
  "created": true,
  "ports": {"db": 10011, "web": 10010}
}
```

Columns: `branch path base upstream created`.

### status

A list of worktree records. Which worktrees depends on the view:

| Invocation | Records |
|------------|---------|
| `git hop status` (in a hub) | Every branch registered in the hub, sorted by branch |
| `git hop status <branch>` | The one record for `<branch>` (a one-element list); exit 1 if the branch is not in the hub |
| `git hop status --all` | Every worktree of every tracked repository, by repository then branch; works outside a hub |

Outside a hub, plain `git hop status` in a structured mode exits 128. The
human `--all` summary (paths, counts, disk use) is not part of the result.

| Field | Type | Meaning |
|-------|------|---------|
| `branch` | string | Branch name |
| `base` | string | Branch the sync status is computed against |
| `state` | string | `Linked` when the worktree directory is at its path, `Occupied` when something that is not a directory is (a file, or a symlink to one or to nothing), `Missing` when nothing is |
| `status` | string | Sync label: `default`, `synced`, `merged`, `merged (N behind)`, `behind (N)`, `N ahead`, `diverged (N ahead, M behind)`, `unknown`; a dirty suffix may follow; `-` when the state is not `Linked` |
| `path` | string | Absolute path of the worktree |
| `repository` | string | *json/yaml only*; `status --all` only. Repository id (`host/org/repo`) |
| `hub` | string | *json/yaml only*. Absolute path of the hub the worktree belongs to; with `--all`, absent when state does not know it |
| `ports` | map service → port | *json/yaml only*; `status <branch>` only, when ports are allocated |
| `services` | list of `{service, name, state}` | *json/yaml only*; `status <branch>` only, the worktree's Docker Compose containers (compose service, container name, container state such as `running` or `exited`) |

```json
[
  {
    "branch": "feat/login",
    "base": "main",
    "state": "Linked",
    "status": "2 ahead",
    "path": "/home/me/src/widget/hops/feat/login",
    "hub": "/home/me/src/widget"
  },
  {
    "branch": "main",
    "base": "main",
    "state": "Linked",
    "status": "default",
    "path": "/home/me/src/widget/hops/main",
    "hub": "/home/me/src/widget"
  }
]
```

Columns: `branch base state status path`.

### list

A list of worktree records, sorted by repository then branch: the current
repository's worktrees inside a hub, every tracked repository's outside
one.

| Field | Type | Meaning |
|-------|------|---------|
| `repository` | string | Repository id (`host/org/repo`) |
| `branch` | string | Branch name |
| `base` | string | Branch the sync status is computed against |
| `type` | string | Worktree type recorded in state (`bare` or `linked`) |
| `path` | string | Absolute path of the worktree |
| `state` | string | `active` when the worktree directory exists, `missing` otherwise |
| `status` | string | Sync label, as in `status`; `-` when missing |
| `hub` | string | *json/yaml only*. Absolute path of the hub the worktree belongs to; absent when state does not know it |

Records of two hubs of one repository can share a branch; `path` and
`hub` tell them apart.

```json
[
  {
    "repository": "github.com/acme/widget",
    "branch": "feat/login",
    "base": "main",
    "type": "linked",
    "path": "/home/me/src/widget/hops/feat/login",
    "state": "active",
    "status": "2 ahead",
    "hub": "/home/me/src/widget"
  }
]
```

Columns: `repository branch base type path state status`.

### remove

A list of records, in every form: `remove <branch>` gives one, `remove
--merged` one per candidate (sorted by branch, removed or left in place),
and `remove <hub>` one per worktree (sorted by branch), then the hub, then
the repository's data-home hopspace when it exists. `--merged` with nothing
to remove gives `[]`. When `--merged` leaves a candidate in place (safety
gate, failure) the records still print and the exit status is 1.

| Field | Type | Meaning |
|-------|------|---------|
| `kind` | string | `worktree` (a branch worktree), `hub` (the hub directory), `hopspace` (the data-home hopspace, `remove <hub>` only) |
| `branch` | string | Branch of a `worktree` record; empty for `hub` and `hopspace` |
| `path` | string | Absolute path of the worktree, hub or hopspace |
| `removed` | bool | `true` when removed (or, under `--dry-run`, would be); `false` when left in place (see `reason`) |
| `branch_deleted` | bool | `true` when the local branch was deleted; `false` when it was already absent, or for a hub's worktrees (the hub goes with its repository) |
| `remote_deleted` | bool | `true` when the branch was deleted on origin (`--delete-remote`); under `--dry-run`, `true` when `--delete-remote` would try (origin is not probed) |
| `reason` | string | *json/yaml only*; why the entry was left in place: the safety gate's refusal, a failure, a `--merged` skip (current worktree, missing path), a hopspace still used by another hub; absent when removed |
| `dry_run` | bool | *json/yaml only*; `true` under `--dry-run`, absent otherwise |

```json
[
  {
    "kind": "worktree",
    "branch": "feat/login",
    "path": "/home/me/src/widget/hops/feat/login",
    "removed": true,
    "branch_deleted": true,
    "remote_deleted": false
  }
]
```

Columns: `kind branch path removed branch_deleted remote_deleted`.

### move

One object.

| Field | Type | Meaning |
|-------|------|---------|
| `old_branch` | string | Branch before the move |
| `new_branch` | string | Branch after the move |
| `old_path` | string | Absolute worktree path before the move |
| `new_path` | string | Absolute worktree path after the move |
| `current_updated` | bool | `true` when the hub's `current` symlink pointed at the worktree and now follows it (or, under `--dry-run`, would) |
| `dry_run` | bool | *json/yaml only*; `true` under `--dry-run`, absent otherwise |

```json
{
  "old_branch": "feat/login",

  "old_path": "/home/me/src/widget/hops/feat/login",
  "new_path": "/home/me/src/widget/hops/feat/sign-in",

}
```

Columns: `old_branch new_branch old_path new_path current_updated`.

### merge

One object. A merge that stops on conflicts exits 1 with no result (as
does its `--dry-run` preview); the receiving worktree is left mid-merge,
as `git merge` leaves it.

| Field | Type | Meaning |
|-------|------|---------|
| `source` | string | Branch merged |
| `into` | string | Receiving branch |
| `result` | string | `up-to-date` (`into` already contained `source`), `fast-forward` (`into` moved to `source`'s tip), `merge-commit` (a merge commit was created; `--no-ff` forces one) |
| `commit` | string | Full id of the commit `into` ends on; under `--dry-run` empty for a `merge-commit`, which does not exist yet |
| `source_removed` | bool | `true` when the source worktree directory was removed (or, under `--dry-run`, would be) |
| `branch_deleted` | bool | `true` when the local source branch was deleted (or would be) |
| `remote_deleted` | bool | `true` when the source branch was deleted on origin (`--delete-remote`, `hop.merge.deleteRemote`); under `--dry-run`, `true` when it would try (origin is not probed) |
| `dry_run` | bool | *json/yaml only*; `true` under `--dry-run`, absent otherwise |

```json
{
  "source": "feat/login",
  "into": "main",
  "result": "fast-forward",
  "commit": "9f1c2e7b4a0d3c8e6b5f2a1d7c9e0b4f3a6d8c21",
  "source_removed": true,
  "branch_deleted": true,
  "remote_deleted": false
}
```

Columns: `source into result commit source_removed branch_deleted remote_deleted`.

### root command

`git hop <branch>` (switch), `git hop <uri> [<path>]` (clone) and
`git hop <uri> --branch <b>` inside a hub (fork-attach) render one
object, told apart by `action`. The root command carries one result
shape whatever it does: the columns every action fills, and json/yaml
only fields that one action fills and the others leave out. Only switch
has a preview; clone and fork-attach refuse `--dry-run` (exit 129). On exit 93
(a `post-worktree-switch` hook navigated itself) the switch succeeded
and the result still prints. The bare `git hop` prints help and no
result.

| Field | Type | Meaning |
|-------|------|---------|
| `action` | string | `switched`: an existing worktree became current; `cloned`: a new hub and its default branch's worktree were created; `fork-attached`: a fork's branch was attached to the current hub |
| `branch` | string | Branch of the worktree the run landed on: the one switched to, the default branch (`cloned`), or the hub branch the fork's branch became, `<branch>-fork-<owner>` (`fork-attached`) |
| `path` | string | Absolute path of that worktree |
| `hub` | string | Absolute path of the hub (the new one for `cloned`) |
| `uri` | string | *json/yaml only*; `cloned`: the origin cloned; `fork-attached`: the fork's URI |
| `default_branch` | string | *json/yaml only*; `cloned` only: the origin's default branch |
| `fork_branch` | string | *json/yaml only*; `fork-attached` only: the fork's branch that was attached |
| `current_updated` | bool | *json/yaml only*; `switched` only: `true` when the hub's `current` symlink now points at the worktree (or, under `--dry-run`, would); `false` when writing it failed |
| `dry_run` | bool | *json/yaml only*; `true` under `--dry-run`, absent otherwise |

```json
{
  "action": "switched",
  "branch": "feat/login",
  "path": "/home/me/src/widget/hops/feat/login",
  "hub": "/home/me/src/widget",
  "current_updated": true
}
```

```json
{
  "action": "cloned",
  "branch": "main",
  "path": "/home/me/src/widget/hops/main",
  "hub": "/home/me/src/widget",
  "uri": "git@github.com:acme/widget.git",
  "default_branch": "main"
}
```

```json
{
  "action": "fork-attached",
  "branch": "feat/login-fork-alice",
  "path": "/home/me/src/widget/hops/feat/login-fork-alice",
  "hub": "/home/me/src/widget",
  "uri": "git@github.com:alice/widget.git",
  "fork_branch": "feat/login"
}
```

Columns: `action branch path hub`.

The shell integration reads only the exit status and asks
`git hop __current-path` where to `cd`, so a structured switch still
moves the shell.

### doctor

A list of findings and repairs, in the order the checks ran. A healthy run
returns `[]`. The exit status is 1 when an `issue` is left without a
matching `fixed` (or `would-fix`) record, or any repair `failed`; see
[git hop doctor](#git-hop-doctor).

| Field | Type | Meaning |
|-------|------|---------|
| `kind` | string | `issue` (makes the installation unhealthy), `warning` (reported, harmless), `fixed` (repaired by `--fix`), `would-fix` (`--fix --dry-run` would repair it), `failed` (`--fix` could not repair it) |
| `check` | string | `paths`, `hub`, `hopspace` (a stale data-home hopspace copy beside a default hub, hopspace hooks or a hopspace at another `hop.dataLayout` location, a `--global` hopspace record of a hub that no longer exists), `dependencies`, `ports` (a port two worktrees hold, across every hub), `worktrees`, `state` or `config` (a broken `managers.json`, a leftover `config.json` git-hop does not read, a leftover `hops.json` git-hop no longer uses, a `--global` `hop.*` key left by the old `global.json` migration, a retired `hop.*` setting, or the current hub's repository format). The published output schema lists all eight |
| `subject` | string | What the record is about: a path, a branch, a dependency directory, or a git config key. `state` records about a worktree name the worktree's path (two hubs can each have a worktree of the same branch); only an entry without a path, kept from a state file an earlier release wrote, is named `repository:branch` |
| `message` | string | Human-readable description; for repairs, the repair itself (`create data directory`) |
| `fixable` | bool | *json/yaml only*; `issue` records only: `true` when `--fix` has a repair for it (which can still come out `failed`), `false` when it has none and the message or `hint:` says what to do instead (a broken `managers.json`, a state key collision, a missing origin fetch refspec, an unmerged branch's worktree path occupied by something else). Absent on other kinds |

```json
[
  {
    "kind": "issue",
    "check": "state",
    "subject": "/home/me/src/widget/hops/feat/old",
    "message": "worktree missing: /home/me/src/widget/hops/feat/old (github.com/acme/widget:feat/old)"
  },
  {
    "kind": "warning",
    "check": "config",
    "subject": "/home/me/.config/git-hop/config.json",
    "message": "not read; git-hop settings live in git config hop.*; you can delete the file"
  }
]
```

Columns: `kind check subject message`.

### prune

A list of the entries removed, or with `--dry-run` the entries that would
be, in the order the passes run: hop.json entries, state worktrees, state
hubs, repair backups, conversion backups, `hop.json` temp files, and with `--all` state backups and `state.json` temp files. Entries left in place although
their path is missing (a worktree git has locked) are listed as `skipped`,
with or without `--dry-run`.

| Field | Type | Meaning |
|-------|------|---------|
| `action` | string | `pruned`, or `would-prune` under `--dry-run`; `skipped` for an entry left in place (see `reason`) |
| `kind` | string | `worktree` or `hub` (state file entries), `hop-json-entry` (a hub's `hop.json` branch entry), `repair-backup` (an expired repair snapshot), `conversion-backup` (an expired `git hop init` backup), `state-backup` (an expired copy of `state.json`, `--all` only), `temp-file` (a temp file an interrupted save of `hop.json`, or with `--all` of `state.json`, left behind) |
| `repository` | string | Repository id the entry belongs to; empty for `state-backup` and a `state.json` `temp-file` |
| `branch` | string | Branch of a `worktree` or `hop-json-entry`; empty otherwise |
| `path` | string | Worktree, hub, backup or temp file path the entry pointed at |
| `reason` | string | *json/yaml only*, `skipped` entries only: why it was left in place, e.g. `locked in git: on the usb drive` |

```json
[
  {
    "action": "would-prune",
    "kind": "worktree",
    "repository": "github.com/acme/widget",
    "branch": "feat/old",
    "path": "/home/me/src/widget/hops/feat/old"
  }
]
```

Columns: `action kind repository branch path`.

### env gc

A list of orphaned dependency directories deleted, or with `--dry-run`
that would be, sorted by key. Without `--no-prompt` (or `--force`) a
structured run has no way to confirm and exits 129 instead of deleting.

| Field | Type | Meaning |
|-------|------|---------|
| `action` | string | `deleted`, or `would-delete` under `--dry-run` |
| `key` | string | Dependency key, its path under the hopspace's `deps/`: `<lockfile hash>/<deps dir>`, or `<deps dir>.<lockfile hash>` for an install an earlier release made; for a store an earlier release left under the data home, its path there (`<name>/deps`); for a compose override cache, its path under the cache directory (`<org>/<repo>/...`) |
| `size` | integer | Size in bytes |
| `last_used` | string | When a worktree last used it (RFC 3339, UTC); empty when unknown |
| `path` | string | Absolute path of the dependency directory |

```json
[
  {
    "action": "would-delete",
    "key": "5e0c7d2a91b4/node_modules",
    "size": 184320000,
    "last_used": "2026-08-02T14:05:11Z",
    "path": "/home/me/src/widget/deps/5e0c7d2a91b4/node_modules"
  }
]
```

Columns: `action key size last_used path`.

### repair

The repair plan: one record per worktree action, in plan order. The plan
is emitted before it is applied; the exit status says whether it was
(`-n` never applies it). `--list-backups` and `--undo` have no structured
result and exit 129 in the structured modes, before anything is restored.

| Field | Type | Meaning |
|-------|------|---------|
| `status` | string | `repaired` when the plan changes this worktree, `ok` when it needs nothing |
| `path` | string | Absolute path of the worktree |
| `kind` | string | `noop`, `rewrite-gitdir`, `register`, `unregister`, `update-hopjson`, `record-base`, `restore-fetch-refspec` |
| `old` | string | Value before the action, when the kind has one |
| `new` | string | Value after the action, when the kind has one |
| `reason` | string | *json/yaml only*; why the planner chose the action |

```json
[
  {
    "status": "ok",
    "path": "/home/me/src/widget/hops/main",
    "kind": "noop",
    "old": "",
    "new": "",
    "reason": ""
  },
  {
    "status": "repaired",
    "path": "/home/me/src/widget/hops/feat/old",
    "kind": "unregister",
    "old": "",
    "new": "",
    "reason": "directory missing on disk but still registered in git"
  }
]
```

Columns: `status path kind old new`, the line format repair --porcelain has always printed.

### init

One object, whichever mode init runs in; `action` says which. Register
as-is (menu option 3) is only offered by the interactive menu, which a
structured run cannot show: a structured `init` without `--no-prompt` on a
standard repository exits 129 before converting. The menu, the dry-run
plan, the project tree and the backup lines are the human view and never
reach stdout.

| `action` | When |
|----------|------|
| `converted` | A standard repository was converted (`--no-prompt`, `--regular`) |
| `adopted` | A hub git-hop did not create (a bare clone made with plain git) got its missing `hop.json` and was recorded in state |
| `already-initialized` | The hub was set up already; nothing was created |
| `restored` | `--restore <backup>` put a conversion backup back |

Under `--dry-run` every mode reports the result the real run would have,
with `dry_run: true`, and changes nothing; a refusal (occupied restore
target without `--force`, dirty tree) fails the same way as the real run.

| Field | Type | Meaning |
|-------|------|---------|
| `action` | string | See above |
| `hub` | string | Absolute path of the hub; for `restored`, the location the backup was restored to |
| `layout` | string | `bare` (bare repository, worktrees under `hops/`) or `regular` (the repository root is the default branch's worktree); empty for `restored` |
| `default_branch` | string | Default branch of the hub; empty for `restored` |
| `backup` | string | The conversion backup taken (`converted`; empty under `--dry-run`) or restored from (`restored`); empty otherwise |
| `dry_run` | bool | *json/yaml only*; `true` when `--dry-run` previewed the run and changed nothing; absent otherwise |
| `backup_kept` | bool | *json/yaml only*; `true` when the backup is still on disk (`--keep-backup`, `hop.backup.keepBackup`; under `--dry-run`, would be); absent otherwise |
| `registered` | bool | *json/yaml only*; `true` when this run recorded the hub in git-hop's state (`converted`, `adopted`; under `--dry-run`, would); absent otherwise |
| `worktrees` | list of `{branch, path, action, moved_from}` | *json/yaml only*; see below. `[]` when none |
| `moved_aside` | string | *json/yaml only*; `restored` with `--force`: where what occupied the original location was moved (would be, under `--dry-run`) |

`worktrees` lists the worktree this run created, then each linked
worktree a bare conversion carried into the hub, in the order of their
git admin directories; under `--dry-run`, the ones it would create and
carry. A prunable linked worktree is left behind and not listed; a
regular conversion carries none.

| Field | Type | Meaning |
|-------|------|---------|
| `branch` | string | Branch checked out in the worktree; empty for a carried worktree on a detached HEAD |
| `path` | string | Absolute path of the worktree; for a carried one, where it is after the conversion |
| `action` | string | `created` (init checked the worktree out) or `carried` (a linked worktree of the converted repository, adopted by the hub: one outside the working tree stays where it is, one inside moves to `hops/<branch>`) |
| `moved_from` | string | `carried` only: the worktree's path before the conversion, when it moved into `hops/`; absent otherwise |

```json
{
  "action": "converted",
  "hub": "/home/me/src/widget",
  "layout": "bare",
  "default_branch": "main",
  "backup": "/home/me/.cache/git-hop/acme-widget/2026-09-25_10-12-03",
  "registered": true,
  "worktrees": [
    {"branch": "main", "path": "/home/me/src/widget/hops/main", "action": "created"},
    {"branch": "feat/login", "path": "/home/me/src/widget/hops/feat/login", "action": "carried",
     "moved_from": "/home/me/src/widget/.worktrees/login"},
    {"branch": "spike", "path": "/home/me/scratch/widget-spike", "action": "carried"}
  ]
}
```

Columns: `action hub layout default_branch backup`.

### env start, env stop

One object: the worktree's environment once the start or stop has run.
The manager's steps, hook output and the lifecycle command's own output
stay on stderr. A worktree with no environment is not an error: `manager`
is empty and `env_started` (`env_stopped`) is `false`. `env start` and
`env stop` have no preview; `--dry-run` exits 129.

| Field | Type | Meaning |
|-------|------|---------|
| `branch` | string | Branch checked out in the worktree |
| `path` | string | Absolute path of the worktree |
| `manager` | string | Environment manager that ran (for example `docker-compose`); empty when the worktree has none |
| `env_started` | bool | `env start` only: `true` when the environment was started |
| `env_stopped` | bool | `env stop` only: `true` when the environment was stopped |
| `ports` | map service → port | *json/yaml only*; ports allocated to the worktree's services; absent when none |
| `services` | list of `{service, name, state}` | *json/yaml only*; `docker-compose` only: the worktree's containers after the run, as `docker compose ps` reports them (as in `status <branch>`); absent when it reports none |

```json
{
  "branch": "feat/login",
  "path": "/home/me/src/widget/hops/feat/login",
  "manager": "docker-compose",
  "env_started": true,
  "ports": {"db": 10011, "web": 10010},
  "services": [
    {"service": "db", "name": "widget-feat-login-db-1", "state": "running"},
    {"service": "web", "name": "widget-feat-login-web-1", "state": "running"}
  ]
}
```

```json
{
  "branch": "feat/login",
  "path": "/home/me/src/widget/hops/feat/login",
  "manager": "docker-compose",
  "env_stopped": true,
  "ports": {"db": 10011, "web": 10010}
}
```

Columns: `branch path manager env_started` (env start), `branch path manager env_stopped` (env stop).

### env generate

One object: the environment files written for the current worktree.

| Field | Type | Meaning |
|-------|------|---------|
| `branch` | string | Branch checked out in the worktree |
| `path` | string | Absolute path of the worktree |
| `generated` | bool | `true` when the files were written; `false` when the worktree has no Docker environment |
| `env_file` | string | Absolute path of the worktree's `.env`; empty when not generated |
| `override` | string | Absolute path of the branch's compose override, which replaces the compose file's hardcoded host ports; empty when the compose file needs none |
| `ports` | map service → port | *json/yaml only*; ports allocated to the worktree's services; absent when none |

```json
{
  "branch": "feat/login",
  "path": "/home/me/src/widget/hops/feat/login",
  "generated": true,
  "env_file": "/home/me/src/widget/hops/feat/login/.env",
```

## Configuration Reference

### hop.json Schema

A hub's `hop.json` (which is also its hopspace's for a default clone):

```json
{
  "repo": {
    "uri": string,
    "org": string,
    "repo": string,
    "defaultBranch": string,
    "mode": "global"
  },
  "branches": {
    "<branch>": {
      "path": string,
      "hopspaceBranch": string,
      "base": string,
      "task": string,
      "fork": string,
      "exists": boolean,
      "lastSync": string,
      "packageManagers": { "<pm>": { "installCmd": [string] } }
    }
  },
  "settings": {
    "compareBranch": string,
    "environmentManager": string,
    "environmentConfig": {
      "hooks": {
        "preStart": [string], "postStart": [string],
        "preStop": [string], "postStop": [string]
      }
    }
  },
  "packageManagers": { "<pm>": { "installCmd": [string] } },
  "forks": object
}
```

### Fields

`repo` and `branches` are written by git-hop; edit them only to repair a
hub (`git hop repair` does it for you).

| Field | Description |
|-------|-------------|
| `repo.mode` | `global` for a hub cloned with `--global`: its hopspace lives in `$GIT_HOP_DATA_HOME/<org>/<repo>`. Absent otherwise |
| `branches.<b>.base` | Branch the worktree was created from; `status` and `list` compare against it |
| `branches.<b>.task` | Task id recorded by `git hop add --task` |
| `settings.compareBranch` | Comparison branch for worktrees without a `base`; default `repo.defaultBranch` |
| `settings.environmentManager` | Environment manager to use by name (built-in `docker-compose` or one from `managers.json`); `none` disables it |
| `settings.environmentConfig.hooks` | Command lists run around `env start` / `env stop` |
| `packageManagers.<pm>.installCmd` | Install command for package manager `<pm>` in this repository |
| `branches.<b>.packageManagers.<pm>.installCmd` | The same for one branch; wins over the repository's |

Whether add and clone start the new worktree's environment is not a
`hop.json` field: it is `git config hop.env.autoStart` (default `false`),
overridden by `$GIT_HOP_AUTO_ENV_START` and `--[no-]env-start`. An old
`settings.autoEnvStart` in `hop.json` is kept but not read, as are
`settings.envPatterns` and `migrated`, which earlier releases wrote.

### ports.json and volumes.json

The hopspace's `ports.json` holds the port range and allocation mode, and
each worktree's ports; `volumes.json` the volume base path and each
worktree's volume directories. git-hop creates both the first time a
worktree with a compose file gets its environment generated.

| Field | Default | Description |
|-------|---------|-------------|
| `ports.json` `baseRange.start` / `baseRange.end` | `10000` / `20000` | Range new ports come from |
| `ports.json` `allocationMode` | `incremental` | `incremental`: after the highest port in use; `hash` (any other value): where the repository, hub and branch hash to |
| `volumes.json` `basePath` | `<hopspace>/volumes` | Where volume directories go |

A worktree keeps the ports and volume directories its entry records. Ports
are allocated against every hub git-hop knows of; see
[Configuration](configuration.md#ports-and-volumes).

## Environment Variables

| Variable | Description | Default |
|----------|-------------|----------|
| `GIT_HOP_DATA_HOME` | Data directory | `$XDG_DATA_HOME/git-hop` (Linux/Unix: `~/.local/share/git-hop`, macOS: `~/Library/Application Support/git-hop`, Windows: `%LOCALAPPDATA%\git-hop`) |
| `XDG_CONFIG_HOME`, `XDG_STATE_HOME`, `XDG_CACHE_HOME` | Config, state and cache directories, with `git-hop/` under each; there are no git-hop variables for them | OS defaults (Linux/Unix: `~/.config`, `~/.local/state`, `~/.cache`) |
| `GIT_HOP_ADD_FROM` | Start-point for `git hop add`'s new branches; overrides `git config hop.add.defaultStartPoint`, `--from` wins | unset |
| `GIT_HOP_HOOKS` | How clone and init mirror committed `.git-hop/hooks/`; overrides `git config hop.hooks.installMode`, `--hooks` wins | unset |
| `GIT_HOP_AUTO_ENV_START` | Overrides `git config hop.env.autoStart` for add and clone (`true`/`false`, git's boolean spellings; anything else is fatal); `--[no-]env-start` wins over it | unset |
| `GIT_HOP_NO_CHDIR_HOOK` | When non-empty, the shell integration stops dispatching `post-worktree-switch` on a plain `cd` | unset |
| `GIT_HOP_VERBOSE` | Debug switch, like git's `GIT_TRACE`: stands in for `-V` on every run. `true`/`yes`/`on` is `-V`, `false`/`no`/`off` or empty is off (any case), a number is the `-V` count (`2` is `-VV`); anything else prints a warning and counts as off. A `--verbose` on the command line wins, so `--verbose=0` turns it off for one run | unset |

No other global flag has an environment variable.

### Variables set for hooks

git-hop exports these *into* lifecycle hooks; you do not set them yourself. See [Hooks System](https://github.com/hop-top/git/blob/main/docs/hooks.md).

| Variable | Set for | Description |
|----------|---------|-------------|
| `GIT_HOP_HOOK_NAME` | all (except `pre/post-repair`) | Name of the hook being run |
| `GIT_HOP_WORKTREE_PATH` | all (except `pre/post-repair`) | Absolute worktree path |
| `GIT_HOP_REPO_ID` | all (except `pre/post-repair`) | `<host>/<org>/<repo>`: the host of the origin URL, or `hop.gitDomain` when it has none |
| `GIT_HOP_BRANCH` | all (except `pre/post-repair`) | Branch name; empty for `pre-clone` |
| `GIT_HOP_OLD_BRANCH`, `GIT_HOP_NEW_BRANCH`, `GIT_HOP_OLD_PATH`, `GIT_HOP_NEW_PATH` | `pre/post-worktree-move` | Before/after branch and path |
| `GIT_HOP_FROM_BRANCH`, `GIT_HOP_FROM_WORKTREE_PATH` | `pre/post-worktree-switch` | Worktree being left. **Absent, not empty**, when there is no previous worktree |
| `GIT_HOP_TRIGGER` | `pre/post-worktree-switch` | `hop` or `chdir` |
| `GIT_HOP_TASK` | `pre/post-worktree-add` with `--task` | The task id. **Absent, not empty**, without `--task` |
| `GIT_HOP_BRANCH_TYPE`, `GIT_HOP_BRANCH_NAME`, `GIT_HOP_BRANCH_PREFIX`, `GIT_HOP_BRANCH_PARENT`, `GIT_HOP_BRANCH_START_POINT`, `GIT_HOP_DETECTOR_SOURCE` | hooks dispatched with a detector | Branch-type detection results |

`pre-repair` and `post-repair` receive **none** of the above; they run with the hub as their working directory and the ambient environment only.

### Data Directory Resolution

git-hop uses the following priority for determining the data directory:

1. `$GIT_HOP_DATA_HOME` (if set)
2. `$XDG_DATA_HOME/git-hop` (if `$XDG_DATA_HOME` is set)
3. OS-specific defaults:
   - **Linux/Unix**: `~/.local/share/git-hop`
   - **macOS**: `~/Library/Application Support/git-hop`
   - **Windows**: `%LOCALAPPDATA%\git-hop`

## Exit Codes

git-hop follows git's porcelain statuses. Per-command tables above say
which apply where.

| Code | Description |
|------|-------------|
| 0 | Success |
| 1 | Operation failure: every `fatal:` or `error:` not listed below (not found, refused, failed) |
| 128 | Fatal repository or environment error: `git hop repair` cannot lock or find the hub, structured `status` outside a hub, `$GIT_HOP_AUTO_ENV_START` not a boolean |
| 129 | Usage error: unknown flag or subcommand, wrong arguments, `--dry-run` on a command that cannot preview, contradictory or unknown output options, structured output asked of a command with no result shape, or a confirmation prompt with no readable stdin (`remove`, `env gc`, `init`; pass `--no-prompt`) |
| 93 | `git hop <branch>` succeeded and a `post-worktree-switch` hook reported that it handled navigation itself. The shell wrapper turns this into 0 and skips its `cd`. Not a failure |
