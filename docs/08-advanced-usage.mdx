# Advanced Usage

git-hop offers advanced features for power users and complex workflows.

## Custom Hooks

Create custom lifecycle hooks to automate workflows. These are git-hop's own hooks, not git's — they never live in `.git/hooks/`, and hook names like `pre-commit` mean nothing here. See [Hooks System](https://github.com/hop-top/git/blob/main/docs/hooks.md) for the exhaustive list of valid names.

### Hook Locations

git-hop looks for hooks in these locations (in priority order):

1. `<worktree>/.git-hop/hooks/<name>` — plus a walk up parent directories
2. `$GIT_HOP_DATA_HOME/<org>/<repo>/hooks/<name>` — the hopspace (laid out
   by `hop.dataLayout`), then `$GIT_HOP_DATA_HOME/github.com/<org>/<repo>/hooks/<name>`,
   where earlier releases mirrored hooks
3. `$XDG_CONFIG_HOME/git-hop/hooks/<name>` — global

First found wins; a missing hook is a silent no-op. Hooks must be executable.

### Example: Validate Branch Names

```bash
# .git-hop/hooks/pre-worktree-add
#!/bin/bash

if [[ ! "$GIT_HOP_BRANCH" =~ ^(feature|bugfix|hotfix|release)/ ]]; then
    echo "Branch must start with feature/, bugfix/, hotfix/, or release/"
    exit 1
fi
```

A non-zero exit from a `pre-` hook aborts the operation.

### Example: Bootstrap a New Worktree

```bash
# .git-hop/hooks/post-worktree-add
#!/bin/bash

cd "$GIT_HOP_WORKTREE_PATH"

# Shared deps are already linked and .env already holds the allocated
# ports: git-hop sets both up before post-worktree-add fires.

# Run migrations
make db-migrate
```

### Example: React to a Worktree Switch

Fires for `git hop <branch>` and for a plain `cd` into a registered worktree — tell them apart with `GIT_HOP_TRIGGER`:

```bash
# .git-hop/hooks/post-worktree-switch
#!/bin/bash

if [ -n "${GIT_HOP_FROM_BRANCH+set}" ]; then
    echo "$GIT_HOP_FROM_BRANCH -> $GIT_HOP_BRANCH (via $GIT_HOP_TRIGGER)"
fi
```

The from-state variables are **absent, not empty**, when there was no previous worktree.

> **Environment services**: hooks around `git hop env start` / `env stop` are a *different* mechanism — shell command strings declared in `hop.json` under `settings.environmentConfig.hooks`, not files. A file named `post-env-start` will never fire. See [Hooks System](https://github.com/hop-top/git/blob/main/docs/hooks.md).

## Port Range

git-hop picks each branch's ports from the range in the hopspace's
`ports.json` (in the hub for a default clone):

```json
{
  "allocationMode": "incremental",
  "baseRange": { "start": 20000, "end": 30000 }
}
```

A worktree keeps the ports its `branches` entry records each time its
environment is generated; only new ports come from the range. See
[Configuration](configuration.md#ports-configuration).

## Cross-Repo Workflows

Work with multiple repositories simultaneously.

### Shared Dependencies

```bash
# Create hub for main project
git hop https://github.com/org/main-project.git
cd main-project

# Create hub for dependency
cd ..
git hop https://github.com/org/shared-lib.git
cd shared-lib

# Both projects have isolated environments
cd ../main-project
git hop feature-x

cd ../shared-lib
git hop bugfix-123
```

## Troubleshooting

### Debug Mode

Enable debug output, as `-V` does, for every command:

```bash
export GIT_HOP_VERBOSE=1
git hop feature-x
```

### Check Configuration

Validate your configuration:

```bash
git hop doctor
```

### Inspect Hopspace

View hopspace details:

```bash
cat hop.json   # in the hub; a --global hub's hopspace is under $GIT_HOP_DATA_HOME/<org>/<repo>/
```

### List All Hopspaces

Find the hopspaces of `--global` hubs:

```bash
find "$GIT_HOP_DATA_HOME" -name "hop.json" -exec dirname {} \;
```

### Orphaned Resources

`git hop prune` drops records, nothing else: state entries and `hop.json`
rows of worktrees and hubs whose directories are gone, the `ports.json`
and `volumes.json` entries of a pruned `--global` hub, and aged-out
backups (see [`git hop prune`](./04-commands#git-hop-prune)). It never
runs Docker, so the containers, networks and Docker volumes of those
worktrees are left as they are, and it never deletes volume directories.

```bash
# Dry run first
git hop prune --dry-run

# Drop the records
git hop prune
```

Neither does `git hop remove`. Stop a worktree's environment before
removing it, while `git hop env stop` can still find it:

```bash
cd hops/feature-x
git hop env stop                    # docker compose stop: the containers stop but stay
docker compose -p <project> down    # removes the containers and their network as well
```

`<project>` is the `project` of the worktree's `ports.json` entry
([Ports Configuration](./configuration.md#ports-configuration)). Once
the worktree and its entry are gone, ask Docker for the projects left
behind:

```bash
docker compose ls --all
docker compose -p <project> down    # add -v to delete its Docker named volumes too
```

Volume directories (`hop_<branch>_<name>` under the hopspace's
`volumes/`, see [Volumes Configuration](./configuration.md#volumes-configuration))
stay when a branch is removed. Removing a hub
moves them aside to `$GIT_HOP_DATA_HOME/orphaned-volumes/<org>/<repo>/`
unless you ask for them to go with it
([Volume data](./04-commands#volume-data)):

```bash
git hop remove <hub-path> --delete-volumes
```

### Port Conflicts

Resolve port conflicts manually:

```bash
# Check what's using a port
lsof -i :8080

# Kill the process
kill -9 <PID>

# Or move the port range in the hopspace's ports.json
vim ports.json
```

### Worktree Corruption

Repair a corrupted worktree:

```bash
# Remove worktree
git worktree remove feature-x

# Re-create with git-hop
cd my-project
git hop feature-x
```

## Performance Tips

### Speed Up Environment Creation

1. **Use Docker volumes**: Avoid rebuilding images
2. **Pre-build images**: Build images once, reuse across branches
3. **Leave auto-start off**: Start services only when needed. It is off
   by default; if you turned it on, turn it off again with

```bash tab="Config"
git config --global hop.env.autoStart false
```

### Reduce Disk Usage

1. **Regular pruning**: Run `git hop prune` regularly
2. **Shared volumes**: Use named volumes for large data
3. **Compress logs**: Rotate and compress service logs

### Optimize Docker

```bash tab="docker-compose.yml"
version: '3.8'
services:
  web:
    image: nginx:alpine
    volumes:
      - web-data:/app/data  # Use named volume
    tmpfs:
      - /tmp              # Use tmpfs for temp files
```
